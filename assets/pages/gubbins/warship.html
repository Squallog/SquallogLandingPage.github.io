Warship

Warship is a 1:72 scale replica of the battleship Bisamrck. I inherrited the project a number of years ago, by which point the hull had been fully constructed but was lacking a superstructure. While I don't find scale modelling particularly appealing, I do think the project has enormous potential as a platform for electronics and software engineering. With a hull exceeding 3 metres, and superstructure exceeding 1.5, the space available for control systems and functionality is immense. My objective with Warship is to build a model which facilitates control of all turrets, cranes, and searchlights. I am aware of 3 other models depicting the same boat at the same scale, while the level of cosmetic detail is impressive, none have achived such a level of functionality.

THE TURRETS

Main Weapons

There are four primary turrets, each with three servos - 2 for gun elevation and 1 for turret traverse. These turrets are each controlled by an Arduino Uno which communicates with a Raspberry Pi using an I2C protocol. The Arduino Uno has a JSON file containing the name and positioning of the turret, these parameters are broadcast through I2C, facilitating "plug and play" functionality between the turrets and central control unit.

Turret Module

The turret module is an Arduino Uno running a Circuit Python script which transmits turret parameters to the central control module while receiving tareting commands and aiming the turrets accordingly. This module is responsible for controlling traverse (axial) and elevation. Traverse movement is controled using a 3 volt DC motor, a potentiometer reading is used to determine turret position. Two microswitches are placed at the extreme limits of turret rotation, on boot the turret is rotated left and then right until it triggers the respective microswitch. Potentiometer values are taken at each of the potentiometer triggers, these values are used to calibrate the relationship between potentiometer value and turret position.

Control Module

A Raspberry Pi acts as a hub, connecting to all of the turrets (primary, secondary, and otherwise) through I2C cables. Commands are received from a web server hosted remotely, with a SIM card facilitating communication. The module receives data telling it the position of a target relative to the center of the boat. Traverse instructions are calculated using the position of each turret (retreived from JSON data inside the turret modules) relative to the center of the boat.

Secondary Turrets

There are 6 secondary turrets, each with 2 servos - 1 for elevation and 1 for traverse.

Air Defence Turrets

There are 8 air defence turrets, these turrets do not have sufficient space inside for any servos or electronics. Elevation and traverse control is acheived using a pair of bicycle brake cables. An F 696Z flange bearing acts as the turret ring, a 6mm diameter basket protrudes through the bearing, with a small connecting horn extending from below such that a brake cable can traverse the turret. A hole of diameter 1.5mm allows a second cable to pass through, with a 5mm socket at its opening to connect the cable housing. Inside the anti aircraft turret, a compression spring keeps the cable under tension and ensures that the turret will elevate when the cable is relaxed.

THE MACHINERY

THE SUPERSTRUCTURE

The superstructure is built around a wooden framework, assembled from lasercut plywood peices, with vertical supports being cut from 6mm ply and horizontal members cut from 3mm. Once complete, plastic paneling will be fixed around the framework. The funnel and foremast are built using 3D printer parts, facilitating their more complex curved geometry.

CONTROL SYSTEM(S)

Two control systems are used - 1 for propulsion and steering, and a second for auxilliary functions. The two control systems are fully isolated circuits, each running from their own batteries.

Propulsion

The propulsion and steering is controlled using a conventional radio receiver and transmitter. This is a simple system with high reliability that, most importantly, requires no supporting infrastructure to operate; the transmitter is always able to communicate with the receiver so long as the boat is within its range.

Auxiliary Functions

Auxilliary functions are controlled through a web-based system. A SIM card will be connected to a Raspberry Pi computer housed within the superstructure. This will communicate with a server hosted elsewhere; a client running on a laptop - also conencted via SIM card - will be sent a control panel from the boat and will send comands into the server. Commands will be relayed into the computer on the boat, which will execute a corresponding function (i.e. aiming turrets). The advantage to this system is twofold: electronics aboard the boat can perform advanced tasks such as converging turrets at a single target or performing a routine; additionally, internet connections are not constrained to a fixed number of channels - this means far more functions can be controlled than would be possible using a conventional radio system. With this said, the drawbacks are also twofold: a cellular connection must be available in oder to use auxilliary functions; and the use of a server introduces a dependency on external infrastructure - if the server goes down while the boat is operating, I will not be able to access it to reboot the system.

REFERENCE MATERIAL

Anatomy of the Ship - The Battleship Bismarck

All reference imagery and diagrams used in the design and assembly of the turrets, superstructure, and machinery are taken from Anatomy of the Ship - The Battleship Bismarck, written by Stefan Draminski. To my knowledge this is the most comprehensive collection of drawings and diagrams for this boat.

German Admiralty

During hull prototyping and construction, prior to my inherritance of the project, measrements were requested directly from German admiralty archives. Letters from this correspondance have been preserved in an album compiled prior to my inherritance of the project.
